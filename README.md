# Модуль оплаты ХуткiГрош (ЕРИП) для Joomla (VirtueMart)

Модуль обеспечивает взаимодействие интернет-магазина на базе **CMS Joomla** с корзиной **VirtueMart** с платёжным сервисом [ХуткiГрош](https://hutkigrosh.by): выставление счетов в ЕРИП (АИС "Расчет"), оплата картой (WebPay), QR-код, автоматическое обновление статусов заказов после оплаты.

## Поддерживаемые версии

Поддерживаются одновременно две версии модуля:

| | [HutkiGrosh API v3](#настройка-hutkigrosh-api-v3) (рекомендуется) | [HutkiGrosh](#настройка-hutkigrosh-предыдущее-поколение) (предыдущее поколение) |
|---|---|---|
| Текущая версия | 2.0.5 (`hutkigrosh_apiv3.zip`) | 1.13.2 (`hutkigrosh.zip`) |
| API | актуальное поколение (REST API v3) | предыдущее поколение API |
| Подключение | API-токен, выбор услуги из списка | логин/пароль, ЕРИП ID вручную |
| Тестовая система | api-sandbox.hgrosh.by | trial.hgrosh.by |
| Кому подходит | новым магазинам и тем, кто переходит на API v3 | действующим магазинам, работает как раньше |

> Сервис ХуткiГрош сейчас поддерживает все поколения API параллельно.

Следите за анонсами о сроках отключения старого API и переходите на API v3 заранее (порядок перехода описан в разделе "[Одновременная работа и переход на API v3](#одновременная-работа-и-переход-на-api-v3)").

Отдельная сборка API v3 обусловлена сменой поколения API сервиса, а не изменениями Joomla: внутри одной версии CMS обе сборки отличаются только поколением API.

## Скачать

Для каждой версии CMS используется свой файл сборки (.zip):

| CMS | Сборка API v3 (рекомендуется) | Сборка предыдущего поколения |
|---|---|---|
| Joomla 3.x + VirtueMart 3.8 | [hutkigrosh_apiv3.zip](https://github.com/esasby/cmsgate-virtuemart-hutkigrosh/blob/master/hutkigrosh_apiv3.zip) | [hutkigrosh.zip](https://github.com/esasby/cmsgate-virtuemart-hutkigrosh/blob/master/hutkigrosh.zip) |

## Требования

- PHP 5.6 и выше, расширения PHP [cURL](https://www.php.net/manual/ru/book.curl.php), dom и simplexml

## Установка (одинакова для обеих версий модуля)

**Joomla 3.x + VirtueMart 3.8:**

1. Создайте резервную копию магазина и базы данных.
1. Скачайте архив нужной сборки (раздел "Скачать").
1. В административной части Joomla выберите `Расширения > Менеджер расширений > Установка > Загрузить Файл пакета`, выберите архив и нажмите `Загрузить`.
1. Перейдите: `Компоненты > VirtueMart > Payment Methods`, выберите способ оплаты **Через систему «Расчет» (ЕРИП)** (создаётся инсталлятором автоматически; для сборки предыдущего поколения, установленной ранее, - имя, заданное при её установке, например `Hutkigrosh`) и откройте вкладку "Конфигурация".

## Настройка HutkiGrosh API v3

### Шаг 1. Получите API-токен

В бизнес-аккаунте ХуткiГрош откройте **Настройки > Интеграция ПУ** (раздел доступен ролям "Владелец ПУ" и "Администратор ПУ"). Используйте токен с доступом к информации о ПУ и созданию/редактированию счетов.

### Шаг 2. Подключите магазин

1. В настройках модуля вставьте токен в поле **API Token**.
1. Нажмите кнопку "Актуализировать" (рядом с полем **API Token**), модуль загрузит из ХуткiГрош справочники для полей **Торговая точка**, **Услуга**, **Кассовое место**.
1. Выберите значения в списках и сохраните изменения.

### Шаг 3. Остальные параметры

**Основное:**
* **Опубликовано**: включен/выключен способ оплаты (стандартное поле способа оплаты VirtueMart).
* **Порядок**: позиция способа оплаты в списке при оформлении заказа (стандартное поле способа оплаты VirtueMart).
* **Путь в дереве ЕРИП**: путь, по которому клиент будет искать выставленный счёт (например, `АИС "Расчет" (ЕРИП) > Интернет-магазины/сервисы >`).
* **Срок действия счета (дней)**: как долго счёт будет доступен в ЕРИП для оплаты (от 1 до 10).
* **Sandbox**: тестовый режим работы, счета выставляются в тестовую систему `api-sandbox.hgrosh.by` с токеном тестовой системы.
* **Debug mode**: запись и отображение дополнительных сообщений при работе модуля (используется при диагностике).

**Экран успешного заказа:**
* **Секция "Инструкция"**: пошаговая инструкция по оплате счёта в ЕРИП.
* **Секция QR-код**: оплата счёта по QR-коду через мобильное приложение банка (QR-код и ссылка на оплату запрашиваются у сервиса).
* **Секция Webpay**: кнопка оплаты счёта картой (переход на Webpay).
* **Текст успешного выставления счета**: может содержать HTML, допустимы переменные `@order_id`, `@order_number`, `@order_total`, `@order_currency`, `@order_fullname`, `@order_phone`, `@order_address`.
* **CSS файл для итогового экрана**: путь к собственному CSS-файлу оформления.

**Статусы заказов** (выбор из существующих статусов магазина, список статусов - `Магазин > Настройки > Статусы`):
* **Статус при выставлении счета**: какой статус установить заказу после выставления счёта в ЕРИП. Рекомендуется "Ожидание" (Pending), заказ ожидает оплаты.
* **Статус при успешной оплате счета**. Рекомендуется "Подтвержден" (Confirmed), оплата получена, заказ ожидает комплектации и отправки.
* **Статус при отмене оплаты счета**. Рекомендуется "Отменен" (Cancelled).
* **Статус при ошибке оплаты счета**. В стандартном наборе VirtueMart нет статуса ошибочной оплаты - рекомендуется "Отменен" (Cancelled) либо созданный собственный статус.

**Уведомления** (отправляются шлюзом ХуткiГрош):
* **Email оповещение**: письмо клиенту при успешном выставлении счёта.
* **Sms оповещение**: SMS клиенту при успешном выставлении счёта.

**Способ оплаты для клиента:**
* Название и описание способа оплаты задаются стандартными полями VirtueMart при редактировании способа оплаты (по умолчанию "Через систему «Расчет» (ЕРИП)").

### Обязательно: адрес обработчика уведомлений

Для автоматического обновления статуса заказа (после оплаты клиентом счёта в ЕРИП) сообщите в службу технической поддержки ХуткiГрош адрес обработчика, указав Ваш домен:

```
https://ваш-домен/index.php?option=com_virtuemart&view=hutkigrosh&task=notify
```

Модуль принимает уведомление GET-запросом с идентификатором счёта (`purchaseid`) в URL.

### Тестовый режим (Sandbox)

1. Получите API-токен тестовой системы (выдаётся при регистрации в ХуткiГрош).
1. Включите в настройках модуля режим **Sandbox**.
1. Счета будут выставляться в тестовую систему `api-sandbox.hgrosh.by`.
1. Для эмуляции оплаты счёта используйте [личный кабинет](https://cabinet.hgrosh.by) (сверху-справа "Профиль пользователя" > "Тестовый режим").

Документация API v3: https://api-dev.hgrosh.by/eripservice/docs/ru/index.html

## Одновременная работа и переход на API v3

* Обе сборки являются одним и тем же расширением (плагин `hutkigrosh` группы `vmpayment`, общий способ оплаты и общие настройки): сборка API v3 устанавливается **поверх** предыдущей версии и замещает её файлы; заказы и данные магазина не затрагиваются. Обратный переход выполняется установкой предыдущей сборки поверх.
* Адрес обработчика уведомлений **не меняется**: сообщать в поддержку ХуткiГрош новый адрес не нужно.
* Способ оплаты в магазине остается один: двойная обработка уведомлений исключена.
* Настройки статусов, текстов и секций сохраняются при переходе; поля подключения меняются: вместо "Логин/Пароль/ЕРИП ID/Код услуги" заполняется "API Token" и справочники "Услуга", "Торговая точка", "Кассовое место" (ранее сохраненные значения остаются в базе данных).

Рекомендуемый порядок перехода:

1. Создайте резервную копию магазина и базы данных.
1. Получите API-токен тестовой системы (см. "Настройка HutkiGrosh API v3", шаг 1).
1. Установите сборку API v3 поверх предыдущей версии (порядок установки см. в разделе "Установка").
1. В настройках модуля вставьте токен в поле "API Token", нажмите "Актуализировать" и выберите значения в списках "Услуга", "Торговая точка", "Кассовое место".
1. Включите режим Sandbox и проверьте выставление и оплату счёта (эмуляция оплаты в личном кабинете тестовой системы, см. "Тестовый режим").
1. Выключите Sandbox и вставьте токен выданный для рабочей системы в поле "API Токен", нажмите "Актуализировать" и выберите значения в списках "Услуга", "Розничная торговая точка", "Кассовое место": счета будут выставляться в рабочую систему.
1. Проверьте обработчик уведомлений: статус заказа в магазине должен измениться после оплаты счёта.

## Логи

Модуль ведет лог файл по пути (название файла `cmsgate.log` для обоих поколений API одинаково):

* сборка API v3: `<корень_сайта>/plugins/vmpayment/hutkigrosh/vendor/apiv3/cmsgate-core/logs/cmsgate.log`
* сборка предыдущего поколения: `<корень_сайта>/plugins/vmpayment/hutkigrosh/vendor/esas/cmsgate-core/logs/cmsgate.log`

Для обеспечения **безопасности** необходимо убедиться, что в настройках http-сервера включена директива `AllowOverride All` для корневой папки.

## Поддержка

По вопросам подключения и работы сервиса обращайтесь в службу технической поддержки [ХуткiГрош](https://hutkigrosh.by).

## Инструкция по сборке

1. Установите зависимости: `composer install` (путь к vendor - `src/vendor`).
1. Архивируйте содержимое каталога `src/` (включая `vendor/`) в `hutkigrosh_apiv3.zip` (сборка только через ZipArchive).
1. При каждой новой сборке увеличивайте версию на +0.0.1 (в `src/hutkigrosh.xml` и `RegistryHutkigroshVirtuemart`).
